# MnemosyneDB

NoSQL key-value база данных на Java. Смотрите также https://github.com/POAL484/HermesDB

> Мнемосина — это древнегреческая богиня памяти и языка, титанида, дочь Урана и Геи

# Запуск в Development режиме

```sh
./gradlew run
```

# Тесты

```sh
./gradlew test
```

# Сборка

```sh
./gradlew distZip distTar
```
Собранные `zip` и `tar` архивы будут находиться `app/build/distributions/`

# Настройка

В папке `resources` - `mnemosyne.properties`

| Ключ | Описание | Поддерживаемые значения | По умолч. |
| :- | - | - | - |
| `cache.algorithm` | Алгоритм для кэша в оперативной памяти | `LRU` `LFU` `TLRU` | `LRU` |
| `storage.disk.enabled` | Сохранять и загружать ли кэш на диск | `false` `true` | `false` |
| `storage.compression.algorithm` | Алгортм сжатия для сохранения на диск | `NONE` `SNAPPY` `GZIP` `LZ4` | `NONE` |

# Поддерживаемые типы хранения

- String
- Java Long-size целочисленные
- Java Double-size числа с плавающей точкой
- boolean
- List
- Map
- Set `{"$set": []}`

# API Docs

Приложение запускает http сервер на локальном порту 5445

## MHRL (`M`nemosyne `H`ermes `R`equests `L`ang)

| Обяз. | Ключ | Тип значения | Описание | Пример |
| - | :- | - | - | - |
| `Да` | `status` | Число | HTTP код | `200` |
| `Не` | `data` | Объект | При успехе: данные ответа конктретной операции | `{"value": "HSSE"}` |
| `Не` | `errCode` | Число | При ошибке: код ошибки, читайте далее | `5` |
| `Не` | `err` | Строка | При ошибке: текстовое сообщение, объясляющее ошибку | `"GETITEM out of bounds in list"` |

```json
{
    "status": 200,
    "data": {
        "value": "HSSE"
    }
}
```

### Коды ошибок `errCode`

- `0` - Не ошибка MHRL
- Отрицательное число - Синтаксическая ошибка
- Положительное число - Сематическая ошибка

| Код | Обозначение |
| :- | - |
| `0` | Не ошибка MHRL. Смотрите `status` |
| `-1` | Ошибка синтаксиса `JSON` или некоректные типы данных в нем |
| `-2` | Неизвестная операция. Проверьте поле `op` |
| `-3` | Необходимые для операции поля запроса не переданны или равны `null` |
| `1` | По ключу несовместимый тип для данной операции |
| `2` | Не найдено значение по ключу, но необходимо для операции |
| `3` | LPOP, RPOP, SREM из пустого списка/множества |
| `4` | GETITEM из списка - индекс вышел за пределы списка |

### Множества через JSON

Для передачи `Set` используется такая логика:
```json
{
    "$set": ["element1", "element2"]
}
```

### GETITEM

Получить значение по индексу/ключу. Работает для списка и отображения

***Необходимые поля***
| Ключ | Тип / Бувальное значение | Описание |
| :- | - | - |
| `op` | `"GETITEM"` | Операция `GETITEM` |
| `key` | `String` | Ключ со списком/отображением |
| `item` | `Int[]` \| `String[]` | Список числовых индексов для получения из списка \| Список ключей для получения из отображения |

***Возвращает***
| Ключ | Тип / Буквальное значение | Описание |
| :- | - | - |
| `value` | `Any[]` \| `Map` | Полученные элемента из списка \| Отображение с полученными по ключам элементами отображения |

***Сематические ошибки:***
| Код | Описание |
| :- | - |
| `1` | По ключу лежит не список/отображение |
| `2` | По ключу не найдено значение |
| `4` | Для списка - индекс вышел за предел списка |

> Если по ключу - список, а в запросе `item[]` имеет не числовое значение - выбросит ошибку `-1`

### INC / DEC

Инкрементирует / декрементирует число на некоторое число

***Необходимые поля***
| Ключ | Тип / Бувальное значение | Описание |
| :- | - | - |
| `op` | `"INC"` \| `"DEC"` | Операция `INC` \| `DEC` |
| `key` | `String` | Ключ для изменения |
| `value` | `Number` | Число для инкрементации \| декрементации |

***Возвращает***
| Ключ | Тип / Буквальное значение | Описание |
| :- | - | - |
| `value` | `Number` | Инкрементированное \| декрементированное число |

***Сематические ошибки:***
| Код | Описание |
| :- | - |
| `1` | По ключу лежит не число |

> Операция поддерживает числа с плавующей точкой. Если попробовать применить операцию к целому числу на дробное число, дробное число округлится вниз

> Если значение по ключу не найдено, создатся новое целое равное нулю, и к нему применится операция. Дробное, опять же, округлится вниз

***Request***

Headers
- String user: валидный UUID4

JSON Body
```json
{
    "key": "String, ключ для даныых"
}
```

***Response***

**OK 200**

JSON Body:
```json
{
    "status": 200,
    "data": CacheDTO
}
```

**Bad request 400**

Возникает при неверном формате JSON или отсутсвующем поле key, или при key == null 

JSON Body: Repsonse со статусом 400

**Unauthorized 401**

Возникает при отсуствии header 'user' или не соответсвия его стандарту UUID4

JSON Body: Response  со статусом 401

**Not found 404**

Возникает при отсуствии значения по ключу key в базе данных

JSON Body: Response со статусом 404
